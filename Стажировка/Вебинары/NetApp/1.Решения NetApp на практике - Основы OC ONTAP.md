NetApp — это ведущий поставщик решений для управления данными и облачной инфраструктуры, который помогает организациям по всему миру преодолевать сложности, связанные с хранением, обработкой и анализом данных. Основанная в 1992 году, NetApp зарекомендовала себя как надежный партнер для бизнеса, предлагая инновационные технологии, которые позволяют клиентам эффективно использовать свои данные для создания конкурентных преимуществ.

Линейки СХД ONTAP делятся на Unified(поддержка всех протоколов доступа) и Block Optimized(протоколы блочного доступа). 
Поколения СХД, относящиеся к Unified системам:
- **NetApp FAS** — гибридные системы хранения, объединяющие производительность флэш и ёмкость HDD. Задержка здесь 5-10 мс. 
- AFF C-Series - работа  только с твердотельными накопителями. В этих системах используются QLC диски(4 бита на ячейку).  *Примечание: чем больше бит на ячейку, тем выше емкость и ниже  цена, но меньше скорость и долговечность*. Задержка здесь 2-4 мс. 
- **NetApp AFF A-Series** — это флагманские All-Flash массивы для критически важных приложений, виртуализации и баз данных. AFF A-Series также используют только  твердотельные  накопители, но уже TLC диски(3 бита на ячейку). Задержка уже меньше  1 мс.

Storage Node(узел/контроллер сервер с англ.) - это узел, имеющий процессор, корпоративные диски, контроллеры с ОС, здесь используется Ontap OC. Материнская плата здесь проприетарная. Возможности OC зависят от самой версии ОС.  
![|212x219](../../images/Решения%20NetApp%20на%20практике%20-%20Основы%20OC%20ONTAP-04.02.2026-11_02-4.png)
Кластер - объединение НОД через кластерную сеть. Объединение имеет общую базу конфигураций, которая  реплицируется по  всем НОДам. На данный момент кластер  можно собрать из максимум 24 узлов. Кластерная сеть может быть разной скорости. NetApp продвигает идет, что  в кластере могут быть системы разных классов, решений, но ,главное, чтобы на всех узлах была одна версия Ontap. Кластер выдает хосту данные как единое целое.
![](../../images/Решения%20NetApp%20на%20практике%20-%20Основы%20OC%20ONTAP-04.02.2026-11_02-5.png)
Надежность - допускается двухконтроллерной архитектурной. HA-pair - два контроллера, соединённые между собой HA interconnect. Cами СХД спроектированы так, чтобы выдерживать единичный отказ контроллера и так далее. 
![](../../images/Решения%20NetApp%20на%20практике%20-%20Основы%20OC%20ONTAP-04.02.2026-11_02-7.png)

Владение дисками. Каждый физический диск принадлежит какому-либо контроллеру, но при этом диски имеют по два порта и подключаются к каждому контроллеру. Однако, у диска один владелец, данные на него записать может только его владелец. Также контроллер Б может отправить через контроллер А какие-либо данные, и контроллер А запишет эти данные на свои диски. 
![](../../images/Решения%20NetApp%20на%20практике%20-%20Основы%20OC%20ONTAP-04.02.2026-11_02-9.png)
Но если например один контроллер  Б вышел из строя, то контроллер А забирает все диски себе. Контроллер А обнаруживает отказ через HA interconnect. Это процедура называется Takeover. Когда контроллер Б приходит снова в действие, то происходит операция Giveback, операция обратная Takeover. 
![](../../images/Решения%20NetApp%20на%20практике%20-%20Основы%20OC%20ONTAP-04.02.2026-11_02-10.png)
Технология NVRAM - энергонезависимая память, защищенная батарейкой, на случай сбоя питания. Гарантируется сохранность памяти в течение 3 суток. Это помогает избежать потерю данных. Это работает так: данные с сервера записываются в Nvram двух контроллеров и в буфер RAM. Дальше контроллер отвечает хосту, что запись прошла, но ,фактически, никакой записи на диски не было.
![](../../images/Решения%20NetApp%20на%20практике%20-%20Основы%20OC%20ONTAP-04.02.2026-11_02-11.png)
Со временем данные записываются в NVRAM и на диски, если система не нагружена, данные записываются каждые 10 секунд. Но данные  записываются на диски из RAM
![](../../images/1.Решения%20NetApp%20на%20практике%20-%20Основы%20OC%20ONTAP-22.03.2026-19_03.png)
Consistency point - состояние, когда из оперативной памяти записываются данные в диски.  После  записи NVRAM и буфер ОЗУ очищаются. Механизм обеспечивает целостность данных:  либо  данные записаны, либо нет и хост знает об этом. При восстановлении системы первое что делает система - проверяет есть ли в NVRAM данные, которые надо записать. 
![](../../images/1.Решения%20NetApp%20на%20практике%20-%20Основы%20OC%20ONTAP-22.03.2026-19_03-1.png)
Aggregate(storage pool) - диски собраны в RAID, но также поверх них WAFL(файловая система, блоки записаны в любом порядке, данные). Для  каждой RAID-группы можем сделать свой Aggregate и свой WAFL. Данные можем писать так, как удобно СХД. 
![](../../images/Решения%20NetApp%20на%20практике%20-%20Основы%20OC%20ONTAP-04.02.2026-11_02-14.png)
WAFL(write anywhere file layout) - unix-файловая система, оканчивающаяся блоками в 4K. Представляет собой  древовидную структуру, где  есть корневой указатель - root pointer. Inodes - промежуточные файлы, содержащие ссылки на другие inodes или на файлы. 
Дальше с https://habr.com/ru/companies/netapp/articles/99832/
Главный принцип, положенный в основу функционирования файловой системы WAFL, отличающий ее от всех тогда существовавших файловых систем, может показаться немного парадоксальным: единожды записанный блок данных в составе файла в дальнейшем не перезаписывается. Он может быть только удален (очищен), но НЕ ПЕРЕЗАПИСАН.  
Таким образом любой блок данных на файловой системе может быть либо «пустым», и тогда он может быть записан, либо «записанным», и тогда он может быть либо считан, либо стерт, когда на него больше не ссылается ни одна запись вышележащей структуры. Запись (перезапись) в уже занятый какими либо данными блок невозможна по внутренней логике файловой системы.  Необходимые же изменения содержимого записанного файла «дописываются» к нему, на свободное пространство файловой системы. 
Такая своеобразная модель позволяет нам получить две важных особенности использования:  
- Превратить случайные (random) записи на систему хранения в последовательные (sequental).
- Очень просто и эффективно организовать так называемые Snapshots, снэпшоты, или мгновенные «снимки» состояния данных на дисках.
![](../../images/Решения%20NetApp%20на%20практике%20-%20Основы%20OC%20ONTAP-04.02.2026-11_02-15.png)
В ONTAP самые известные RAID:
- RAID 4. Его можно увеличивать в размерах, просто добавляя в RAID физические диски, и при этом нет необходимости перестраивать полностью весь RAID, как, например, обстоит дело в случае RAID-5. Если вы используете 5 дисков под данные (и один под parity) в RAID-4, то для того, чтобы увеличить его емкость, вы можете просто добавить в него один, два, и так далее дисков, и емкость RAID-массива немедленно увеличится на объем добавленных дисков. Никакого длительного процесса перестроения недоступного для использования RAID-массива, как в случае RAID-5, не нужно. Здесь RAID Penalty равен 1.
![](../../images/Решения%20NetApp%20на%20практике%20-%20Основы%20OC%20ONTAP-04.02.2026-11_02-16.png)
- RAID DP(dual patiry,diagonal patiry) - запатентованный RAID, в нем добавляется  к  первому  диску четности второй. Функция **RAID-DP** представляет собой реализацию **_RAID 6_** (двойная проверка четности), которая обеспечивает защиту данных при отказе сразу двух носителей. Взаимосвязь **RAID-DP** с файловой системой **_WAFL_** обеспечивает возможность организовать доступ к процедурам контроля четности, не снижая производительности систем. Благодаря этой функции достигается высокий уровень защиты данных и могут выполняться требовательные к ресурсам приложения. Обязателен для SSD дисков.
![](../../images/Решения%20NetApp%20на%20практике%20-%20Основы%20OC%20ONTAP-04.02.2026-11_02-17.png)
- RAID TEC - RAID, способный выдерживать отказ 3 дисков за счет 3 дисков четности HDD. Обязателен для NL-SAS дисков(жесткие диски корпоративного класса, объединяющие надежный интерфейс SAS (двухпортовый, поддержка команд SCSI) с экономичными SATA-накопителями) с объемом с 10 ТБ. 
![](../../images/Решения%20NetApp%20на%20практике%20-%20Основы%20OC%20ONTAP-04.02.2026-11_02-18.png)

### Volumes
NetApp FlexVol (Flexible Volume) — это технология виртуализации томов в системах хранения данных (СХД) NetApp, представляющая собой гибкие, логические контейнеры данных. Они создаются внутри агрегатов (физических пулов дисков), обеспечивая возможность динамического изменения размера, быстрого выделения ресурсов (thin provisioning) и эффективного управления емкостью без прерывания работы. Можно назначить aggregate несколько томов, каждый из которых предназначен для отдельного приложения или службы. Но надо обязательно  следить за местом самих накопителей. 
![](../../images/Решения%20NetApp%20на%20практике%20-%20Основы%20OC%20ONTAP-04.02.2026-11_02-19.png)
FlexGroup - это масштабируемая распределенная система хранения данных в операционной системе ONTAP storage. Она позволяет создать единую файловую систему большой емкости, которая охватывает множество агрегатов и узлов хранения. Том FlexGroup содержит несколько компонентов, которые автоматически и прозрачно распределяют трафик. Компоненты - это базовые тома FlexVol, составляющие том FlexGroup. Доступны  здесь только файловые и объектные протоколы.
![](../../images/Решения%20NetApp%20на%20практике%20-%20Основы%20OC%20ONTAP-04.02.2026-11_02-20.png)
Иерархия СХД:
1. Носители данных
2. Raid groups
3. Aggregate
4. FlexVol, FlexGroups
5. LUNs, Files, Namespaces

Каждый контроллер работает под управлением Ontap OC. Если ОС грузится со флеш-носителя, то помимо образа ОС, есть и другие вещи внутри: репликационная БД, логи и так далее. В качестве хранения всех этих данных выступает Root Aggregate - корневой агрегат. необходима для загрузки ОС. У каждого агрегата свой контроллер. В root volume нельзя писать пользовательские данные. 
![415](../../images/Решения%20NetApp%20на%20практике%20-%20Основы%20OC%20ONTAP-04.02.2026-11_02-24.png)
Расширенное разделение дисков(ADP) позволяет распределять емкость физических дисков, жестких дисков или SSD-накопителей, между агрегатами и контроллерами в паре HA. 
ADP может быть реализовано двумя способами:
-  Разделение емкости диска для хранения данных - корневой агрегат и агрегат данных: поддерживаются для жестких и твердотельных накопителей. Или корневой агрегат и два агрегата данных: поддерживаются только для твердотельных накопителей
- Распределение емкости пула хранения SSD между 2-4 агрегатами для использования в качестве кэша пула флэш-памяти
ADP обеспечивает большую полезную емкость по сравнению с выделением ресурсов с использованием целых или неразделенных дисков:
- Меньше  емкости выделяется для ресурсов корневых агрегатов, что приводит к увеличению емкости агрегатов данных 
- Диски могут совместно использоваться узлами пары HA для резервного копирования
- Диски Parity могут совместно использоваться RAID-группами или объединениями данных
ADP обеспечивает более эффективное использование емкости для хранения данных или кэш-памяти пула флэш-памяти. Позволяет использовать меньшее количество дисков, что снижает общую стоимость конфигурации системы.
ADP Data Partitioning Methods - :
- Root-Data Partitioning. Root-Data Partitioning применяется для того, чтобы каждый диск разбить на две партиции, одна большая (обычно первая, назовём её data-партиция) и другая намного меньшая по размеру (обычно вторая, назовём её root-партиция). Дальше каждая партиция рассматривается как отдельный диск и может иметь независимо первая от второй своего владельца (контроллер). На маленьких партициях создаются root aggregates для обоих контроллеров, а на больших создаются Data Aggregates.
- Root-Data-Data Partitioning - у каждой data части свой хозяин. Разделение на две data партиции делается для того, чтобы оба контроллера могли одновременно записывать данные на одни и те же физические диски. Это экономит диски и балансирует нагрузку.
![](../../images/Решения%20NetApp%20на%20практике%20-%20Основы%20OC%20ONTAP-04.02.2026-11_02-26.png)
Снапшот (Snapshot) у NetApp — это моментальная, доступная только для чтения (read-only) копия тома или агрегата, создаваемая за доли секунды без остановки работы системы. Снимки используют технологию перенаправления записи (WAFL), занимая место только для изменившихся данных, что обеспечивает мгновенное создание, высокую производительность и быстрое восстановление файлов, LUN или томов.
